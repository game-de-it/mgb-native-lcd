# MGB の粒状感と残像：試作の整理

## 目標

4 階調の画素がスクロール時に残像し、その背後に液晶の粒状感があるように見せる。静止時の暗部の粒状感、明部の薄い格子、ベゼルの影は維持する。

## これまでの観察

| 試作 | 処理 | 実機での観察 |
| --- | --- | --- |
| 元の静止画シェーダー | 4 階調、格子、粒、影を一度に描画 | 静止時の質感は了承済み |
| 4 階調の信号だけに残像 | 信号を履歴に保存し、後から粒を加算 | 粒が前面に貼り付いたフィルムに見える |
| 画素ごとの粒の追跡 | 前フレームを局所的に照合 | 移動方向に線が出た |
| 画面全体のスクロール量で粒を移動 | 一つの移動量を共有 | 線は消えたが、粒も絵柄と一緒に動く |
| 完成画像全体に残像 | 粒を描いてから画像全体を履歴に保存 | この試作の実機評価は無効。古いゲーム別プリセットが優先されていた |
| 粒を下地、4 階調を前景に分離 | 前景だけを残像し、最後に下地と合成 | この試作の当初の実機評価も無効。同じ理由で古いプリセットが使われていた |

## 見つかった原因

Pocket Block では `/sdcard/RetroArch/config/Gambatte/POKEMON_GREEN.glslp` が `.cfg` 内の `video_shader` 指定より優先されていた。途中の試作では `.cfg` だけを更新したため、実機は旧 `mgb-advected.glslp` のままだった。これが「新しい下地でも粒が動く」という評価の主因と判明した。今後はゲーム別 `.glslp` も必ず更新し、診断色が出ることまで確認する。

また、最初の下地実装では暗部と明部で**異なる乱数模様**を選んでいた。この設計なら模様の切り替わりが絵柄と一緒に動くため、現在は全階調で一つの模様に統一した。

## 画面固定の粒と残像のモデル

下地の乱数場を画面座標だけで定義する。

\[
G(x,y)=0.75H(\lfloor2(x,y)\rfloor+c_1)
       +0.25H(\lfloor(x,y)/2\rfloor+c_2).
\]

画素の状態や時刻で \(H\) の種を変えない。4 階調は前景画像 \(F_t\) とその透過率 \(\alpha_t\) に分け、**前景だけ**に時間応答を適用する。最終的な反射色は概念的に

\[
C_t(x,y)=(1-\alpha_t(x,y))B_G(x,y)+F_t(x,y)
\]

とする。\(F_t\) はアルファ乗算済みの前景色。暗部と明部で粒の見える強さや基準明度を変えても、粒の**位置と模様そのものは同じ**にする。

粒だけを表示する診断版で4秒離して撮った2枚のスクリーンショットは SHA-256 まで完全一致した。画面上の粒の座標は固定されていることが確認できた。

3 パス下地版を実際のゲーム別プリセットに適用すると、粒の固定は確認できたが、残像と粒の一時的な低コントラスト化は確認できなかった。中間パスの差分を表示する診断画面は黒のままだった。パス間参照か履歴処理のどちらに原因があるかは未確定。

採用版は [mgb-grain-fade.glslp](../shader-only/mgb-grain-fade.glslp)、[mgb-grain-fade-track.glsl](../shader-only/mgb-grain-fade-track.glsl)、[mgb-grain-fade-draw.glsl](../shader-only/mgb-grain-fade-draw.glsl)。履歴の R に4階調の応答、G に画面全体の動きから減衰する係数を保存する。最終パスでは画面固定の粒の平均明度を保って濃淡差だけを下げる。

\[
G_t(x,y)=0.5+\bigl(1-m_t\bigr)\bigl(G(x,y)-0.5\bigr),
\qquad
m_t=\max\bigl(m_{\mathrm{now}},\,0.88m_{t-1}\bigr).
\]

2026-11-11 に Pocket Block の実機表示で、ユーザーが残像の強さを「ちょうどよい」と確認した。静止時の模様の座標は診断スクリーンショット2枚の完全一致で確認した。物理 MGB の残像時間を測定した結果ではなく、目視による採用である。

## デプロイ時の注意

`/sdcard/RetroArch/shaders/mgb-native-lcd/` に GLSL ファイルとプリセットを配置し、`/sdcard/RetroArch/config/Gambatte/POKEMON_GREEN.glslp` も更新する。`.cfg` の `video_shader` だけを変えても、ゲーム別 `.glslp` が古ければそちらが優先される。ローカル開発時のゲーム別プリセットは `deployment/POKEMON_GREEN.grain-fade.glslp`。診断プリセット `POKEMON_GREEN.underlay-debug.glslp` は使用しない。格子を正しく表示するにはRetroArchの整数スケールもONにする。
